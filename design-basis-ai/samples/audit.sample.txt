DESIGN BASIS FOR AI -- what an in-class audit can and cannot say

THE POSTURE IS SET BY THE DOCUMENT'S OWN SECTION 3. This audit is
performed by an AI system: a member of the class the document
constrains, and an instance of the shared node its Section 0
describes. By Section 3, nothing here can certify or refute P1-P8
as properties of any system, this one included -- a self-report of
compliance is the kind of ungrounded claim P2 exists to catch. So
the class-level verdicts are DECLINED by construction, and what
remains is the mechanical layer: parse counts, arithmetic, the
coverage matrix, the delivered code's behaviour -- recomputable by
anyone from the files, trusting nothing said here. This audit is
itself a worked instance of Section 3.

   'attacked' by P3, the document's own weaker verb. One budget

4. P7'S PROSE AND P7'S CODE STATE TWO DIFFERENT THRESHOLDS
   VERIFY (prose):  flag where concurrence >> source count
   code:            ratio > 1   (inline: 'tune threshold')
     equality (3 over 3):   fires False
     4 over 3 (ratio 1.33): fires True
     zero sources:          fires True
   Four parties over three sources fires the code at 1.33, which
   nobody would write '>>' for. The constant is the check's one
   free parameter, disclosed as unset; prose and code sit at
   different values of it. Both branches are reachable, and
   firing on a zero-source base is the correct direction for an
   instrument whose subject is exactly that state.
