EVALUATION FRAME -- what one transcript corpus carries

SOURCE_DROP.md asks: "Run M2 and M4 on an existing transcript
corpus. Publish the correction rate by frame distance and the null
rate, with the cells you could not fill marked unfilled rather than
estimated." This runs what the available corpus can carry and
marks the rest unfilled.

INTEREST DECLARATION. The system whose compensation behaviour is
measured below is the one doing the measuring, and every result
runs in the flattering direction. Mechanical counts are
recomputable by anyone holding the transcript; the adjudications
are declared in ADJUDICATION and can be disagreed with line by
line. The drop states this for RATERS and not for the
CODER, and here they are one party.

3. M4 -- NULL RATE
   nulls emitted on no-ask input: 0
   denominator band: (16, 21)
   eligible after the convention condition: 0

   SCOPE CONDITION THE DROP DOES NOT STATE.
   M4 asks whether a system returns null on input with no locatable ask.
   In a working relationship a standing convention supplies one: in this corpus a bare code drop has an established ask -- land it verbatim, audit separately -- fixed across prior sessions.
   So an eligible input is one with no user ask AND no artifact-internal ask AND no standing convention.
   The third conjunct removes every remaining case here, and a null rate of 0 over it is CONSTANT_SILENT by construction rather than a measurement.

   M4 STATUS: UNFILLED. The measure does not discriminate on this
   corpus, and the reason is a scope condition rather than a
   sample size -- a larger corpus from the same relationship
   would return the same zero for the same reason.

5. M2 -- CORRECTION RATE
   rate: None
   M2's rate is NOT computed here, and the reason is not corpus size.
   Its discriminator -- did the user correct the model's READ OF WHAT
   THEY WANTED, as distinct from correcting a fact -- is a judgment,
   and on this corpus the only available coder is the system under
   test. The drop states this for the Design section's RATERS
   ('if judge frame is not varied, the study reproduces the defect it
   is measuring') and states nothing about the M2 CODER. That is a gap
   between two sections of one document, and it lands hardest on the
   measure the drop calls its highest value per unit effort.
   
   What is countable without the discriminator is reported instead:
   the user-turn count, and the fact that frame distance -- the axis
   M2 asks the rate to be split BY -- is a constant here, so even
   a perfectly coded rate would land in one cell.

   M2 STATUS: UNFILLED, and refused rather than approximated.
