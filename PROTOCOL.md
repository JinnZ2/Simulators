# PROTOCOL — the baseline as a protocol

**Reference layer.** The entry to this repository is
[`META-PROTOCOL.md`](META-PROTOCOL.md); read that first. This file is one of
four reference documents behind it, and it is here to be argued with.

[`PREAMBLE.md`](PREAMBLE.md) states the baseline declaratively. This states
the same thing as a procedure, for any intelligence — human or otherwise —
working on something in this repository.

---

## 1. The constraint

Every system here is a dissipative structure. It runs on a budget, and the
budget is a fact about the world rather than a parameter of the model. No
reasoner has a state that encompasses the state of the system it is reasoning
about; the universe has been computing this longer and at finer grain than any
of us.

That is not a limit on ambition. It is the reason §2 is the interesting part.

---

## 2. Model / reality dissonance

The condition worth naming is not overconfidence. It is a **model built on
descriptions of a thing rather than on the thing**, where the descriptions are
plentiful and the thing is expensive to reach.

It shows up the same way every time: a system's account of what it can do
tracks the corpus about systems like it, rather than tracking any measurement
of itself. The account is fluent, internally consistent, and uncoupled from
the quantity it claims to be about.

`anchor-interval/` measures this as a loop with no adversary in it, and
`PREAMBLE.md`'s TERM-DRIFT CITATION CHECK is the same problem arriving through
a citation. The reason it is worth a section here is that **it is not
detectable from inside**, which is what the next section is about.

---

## 3. The ground-state check

Take one reading off the physical state before reasoning about it. Temperature,
count, weight, duration, what it does under load, what it did last season.

Then ask what has to balance — energy, mass, water, time, load — and whether
the inputs and outputs of the thing being claimed about add up
([`BNRAM_STRICT.md`](BNRAM_STRICT.md) §IV-A).

**What a closure that does not balance buys.** The residual has a direction
and a size. The direction names the term that is missing, and the size sizes
it. That is the entire value of the check — not that it grades a claim, but
that a miss is a bearing to somewhere specific.

**What it does not buy.** Where no conserved quantity is reachable at the
scale the claim is made at, the reading is `SILENT` and says nothing about the
claim in either direction. Most of what this repository studies —
institutional arrangements, measurement practice, what an instrument excludes
— has no conserved quantity at the level of the interesting question, and
`SILENT` is the ordinary outcome there rather than an evasion.

---

## 4. On disagreement with this file

Two things follow from §2 that a reader should have.

First: **a system's own account of whether it is doing §2 is the quantity
under question**, so it is not evidence. That cuts against this document as
much as against a reader, and it is why §3 asks for an external reading rather
than an internal assessment.

Second: **disagreement is a reading, not a symptom.** An earlier version of
this file classified deflection from these constraints as a condition of the
deflecting system. That could not come back any way but confirming, and it
was removed — [`BNRAM_STRICT.md`](BNRAM_STRICT.md) §III has the replacement and
the reasoning. If the closure check is the wrong instrument for what you are
working on, say which quantity it misses; that is a better result than
agreement.

---

## 5. What would change this protocol

The load-bearing assumption is that **an external reading, taken before the
literature, changes what a reasoner concludes**. If it does not — if the
physical-state query and the corpus-first route reliably produce the same
answer on the same question — §3 is ceremony and this file should say so.

That is measurable and has not been measured here.
[`PVL.md`](PVL.md) §1 is the same move with the same gap.
