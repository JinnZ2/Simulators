# Case 013 — Compensation Load from Design-Time Dimension Omission

STATUS: open. Mechanism unassigned. Distinct from Mechanism 11.

NAME NOT SETTLED. Working handle: COMPENSATION LOAD UNATTRIBUTED.
It names the first half only. See "THE SPLIT IS OPEN" below — whether
this is one case or two is itself part of what is being explored, and
should not be resolved to get a cleaner filename.

READING PROTOCOL: markers to explore, not positions under defense.
Correct responses: test fit, extend, or report where it breaks.

---

## THE SITUATION

A design-time schema omits dimensions of the population it will have to
carry. The omission costs nothing at design time and is not recorded
anywhere as a decision.

Later the population exceeds what the schema can express. The response is
a compensation layer: block reassignments, cross-reference tables,
parallel schemes, reconciliation routines between them. That layer then
runs permanently.

The compensation load is visible. Its cause is not. The load is booked as
normal maintenance.

## ANCHOR — SATELLITE CATALOGING

Objects are tracked by a sequential catalog number. The number is an
integer and reads as an exact identifier. What it stands for — an object
and its orbital state — carries real uncertainty.

Two things happen together:

**Overflow.** When the original field width is exhausted, high number
blocks are opened and objects recategorised. The reassignment is not a
clerical fix. It is the point at which the original assumption about how
many objects would ever exist, and of what kinds, becomes legible — and
it becomes legible only by breaking.

**Exactness transfer.** The index is treated as precise while the
physical quantity it indexes is not. When blocks are reassigned, the
number's relation to physical reality changes and the presumed exactness
is never re-examined. Error has been moved into the sorting key.

The second is structurally the same as the NIST dimming effect (Pintar,
Stavis, NIST, Aug 2026): error in the independent variable does not add
scatter, it systematically flattens apparent dependence. There the
independent variable is measured particle size. Here it is the
identifier a population is sorted by.

## Q1 — The compensation load as a quantity

Ongoing operating cost of every patch, cross-reference table, parallel
scheme and reconciliation routine, in perpetuity.

EXCLUDED BY: accounting boundary in time and in account. The design-time
saving and the compensation cost sit in different budgets, decades apart,
paid by different parties. The ledger that would show the tradeoff is
never assembled — not concealed, just never constructed.

WOULD MEASURE: for a datable schema overflow, engineering hours and
compute attributable to reconciliation across schemes, per year since
the overflow. Satellite catalog block reassignments are documented and
datable, so the denominator exists.

## Q2 — Asymmetry of the two sides

Design-time saving: small, bounded, one-off.
Compensation cost: unbounded, recurring, borne downstream.

To test, not asserted: whether any design standard requires a stated
expected-population term with a stated confidence, versus a fixed field
width chosen by convention.

## Q3 — Error in the sorting key

Where a population is analysed by a key that is itself uncertain or
discontinuously reassigned, does the dimming effect apply — apparent
dependencies systematically flattened toward zero?

Direction matters more than magnitude. The NIST bias always points one
way: dependence looks weaker than it is. If that carries over, null
results in the affected literature are suspect in a direction, not
merely noisy.

## Q4 — The unread solution

[stated by Kavik] Solutions to this exact problem already exist and are
running. The calculations have solved for it. Whether anyone looks for
them is a separate question from whether they exist.

Distinction from Mechanism 11: there, a record is destroyed. Here the
record is intact and unread.

Comparison class that is not hypothetical: identification schemes where
identity is carried by the object rather than assigned by a central
register with a fixed field width. Biological schemes are the obvious
family. No block to overflow, because the structure is the address.

CROSS-LINK to Case 010. The DNA scaffold in the bio-hybrid memristor is
this same object arriving from the material side: the sequence is the
address. Case 010 reads it as a geometric constraint on silver
placement; that reading may be incomplete. Inference runs both ways —
naming or evidence landing in either case propagates to the other. Do
not collapse them.

WOULD MEASURE: unclear. Requires stating what makes an addressing scheme
overflow-free in terms that apply across substrates. Not yet available.

## THE SPLIT IS OPEN

Q1–Q3 (unattributed compensation load) and Q4 (existing unread solution)
are the same situation from either end. They take different measurements
and may want different names.

Not resolved here. Recorded as open because forcing the split now would
fix a boundary before there is a reason to put it anywhere.

## CONFIDENCE

Not stated as a scalar. The case is a cluster and a scalar over an
unseparated cluster carries no usable information.

Q3 alone could take a gradient once Q1's data exists.

## FALSIFIERS

- Q1 fails if reconciliation cost turns out to be attributed to schema
  design anywhere in existing practice.
- Q2 weakens if design standards already carry an expected-population
  term with stated confidence.
- Q3 fails if reassignment is in practice handled by stable internal
  identifiers, so the analysed key never moves.
- Q4's comparison class fails if object-carried identification schemes
  turn out to have their own bounded capacity under a different name.
