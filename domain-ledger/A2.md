# A2 — CANDIDATE, NOT ADOPTED

A2 in `CLAIM_TABLE.md` records that confidence tracks distance to an anchor
already in a high band, and flags that what makes an anchor *near* versus
*far* is unspecified. That term is what the whole function turns on. This note
records a candidate for it and does not adopt it.

## CANDIDATE

**Anchor distance is load-bearing capacity: how much load an anchor takes
before it moves.**

A hard physical law does not care about the story, so it does not drift while
something is being built on it. It takes unbounded load. A well-corroborated
recent finding takes some. A cultural or incentivised construct moves as soon
as it is leaned on.

Under this reading a near anchor is not near because it is prestigious, well
funded, or heavily studied. It is near because it is *assemblable* — it can be
used as a component in a composition and the composition will hold.

## WHERE IT CAME FROM

Not from the assessment side. From the operating side: hard constraints are
what make a composed solution computable, because a term that will not move
can be leaned on and a soft one cannot. See `../constraint-assembly/`.

The convergence is that both descriptions produce the same ordering.
Thermodynamics and energy systems anchor high, cultural and incentivised
imposition anchors at `none`, and under the candidate that is not two facts
but one: what you can stand on is what does not move.

## WHY IT IS NOT ADOPTED

Adopting it would rewrite the band definitions on a single unexamined
convergence, and the convergence was noticed in the same conversation that
produced both descriptions, which is not independent.

**What would break it:** a case where the two readings come apart.

  - something well-corroborated across many domains that is *not*
    assemblable — cannot be used as a component in a composition
  - something assemblable under load with thin corroboration

Neither has been looked for. Until one search has been run, the candidate is
a shape and not a definition.

## IF IT HOLDS

The anchor map stops being a confidence score and becomes a load table. The
question it answers is not how sure something is, but what can be built on it.
Confidence would then be derived rather than primary — which is a different
architecture from the one currently in `anchor.py`, and would need the module
rewritten rather than amended.

Recorded here rather than in the code for that reason. Nothing in `anchor.py`
has been changed.
