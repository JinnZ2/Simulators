id: RES-001
title: Vehicle functional envelope against local registration mix
status: NOT_MEASURED
term_status: UNNAMED
measurand: Per vehicle model, the functional envelope on four declared axes -- fording depth at which propulsion or control is lost; ash and particulate loading at which intake, filtration or cooling degrades; thermal limit for cabin, battery and control electronics; and behaviour on sensor fault (degrade, limp, refuse to start, or unchanged) -- joined to the share of vehicles by model registered in a given area, and reported as the share of the local fleet remaining functional at each envelope value.
control: Models with a published or certified envelope value on any axis -- military fording ratings, marine engine intake specifications, published battery thermal cutoffs -- which fix a value independently of any inference from a manual or a service bulletin.
scope_limits: Registration mix is by registered address, not by location at any moment, and the two differ most in exactly the conditions the envelope is being read for. Envelope values are per model where the record is per VIN-range, so trim, option and software-version differences are collapsed and the collapse is recorded. Sensor-fault behaviour is software-version dependent and versions change without a registration event, so that axis decays faster than the other three. Emergency-response vehicles are counted where they are registered, which for mutual-aid fleets is not where they respond. No axis is read as a survival probability; each is a stated threshold with a stated source.
thin_links: Reading a manual's warning as an envelope value is an inference over an inference -- the manual states a limit for warranty and liability, liability is a proxy for engineering margin, margin a proxy for the physical threshold; the three are not the same number and the entry marks any manual-sourced value as such. Joining a model-level envelope to a registration count presumes registered models match registered configurations, which is a second thin link on the sensor-fault axis specifically.
would_change: A published envelope value on any axis for any model replaces the inferred one and the row records the replacement. A test programme measuring any axis directly on a consumer model would move that axis from inferred to measured. A registration dataset carrying configuration or software version closes the collapse recorded under scope limits. Any fleet-wide software update re-opens the sensor-fault axis for every affected model, which is why that axis is not carried forward between runs.

## The join

```
    per model                          per area
    ------------------------------     -------------------------
    fording depth        [value]       registration count by model
    ash / particulate    [value]   x   ------------------------- 
    thermal limit        [value]       = share of local fleet
    sensor-fault mode    [mode]          functional at each value
```

The output is a curve per axis: at fording depth d, what share of the
locally registered fleet still moves. Not an average vehicle. Not a
representative vehicle. A distribution, because the envelope values are
not close together and the mix is not uniform across areas.

## The response layer

Fire apparatus, ambulances and National Guard vehicles are rows in the
same table, on the same four axes, joined to the same area. They are not
a separate analysis and they are not assumed to sit outside the
distribution. A plan that assumes the response layer survives a
condition is making a claim on these axes; the entry supplies the axes
and makes no claim.

## Axis notes

```
    FORDING          depth at which propulsion or control is lost.
                     Distinct from the depth at which damage begins;
                     the row carries which one the source states.

    ASH LOADING      intake, filtration, cooling. Includes cabin
                     filtration where the record has it, marked as a
                     separate sub-row because it fails on a different
                     clock from propulsion.

    THERMAL          three separate limits -- cabin, traction battery,
                     control electronics -- never reduced to one
                     number, because they are reached in different
                     orders in different conditions.

    SENSOR FAULT     what the vehicle does, not what it reports.
                     Four declared values; a model whose behaviour is
                     not documented is UNKNOWN, never assumed unchanged.
```

## Not in scope

Recommending vehicles, rating manufacturers, and predicting any event.
The entry produces a fleet-functional curve against a stated condition
axis; it does not say the condition will occur.
