# undeclared-cuts

Open instruments for researchers with lab access.

Each entry is an experiment or a register that **has not been run**. An
entry states a measurand, its scope limits, its thin inferences, and
what would change it. Entries contain no arguments and no findings.

CC0. Standard library only. Phone-buildable.

```
    entries/            one .md per entry, fixed header block
    check_entries.py    header validation + REGISTRY.txt writer
    test_entries.py     the checks on check_entries.py
    REGISTRY.txt        generated -- do not hand-edit
```

## Run

```sh
python3 check_entries.py              # report, then write REGISTRY.txt
python3 check_entries.py --no-write   # report only
python3 test_entries.py               # checks on the checker
```

`check_entries.py` refuses `--selftest` (exit 2) and names the test file.

## Entry header

Twelve keys, `key: value`, one per line, in a contiguous block at the
top of the file, ending at the first blank line. Everything after the
blank line is body and is read by nothing.

```
    id:            stable identifier, never renumbered
    title:         one line
    status:        NOT_MEASURED | UNDERMEASURED | OBSERVED | HELD | PROPOSED
    term_status:   NAMED | UNNAMED       (separate field; any combination legal)
    measurand:     what is being measured, stated as a quantity
    control:       what fixes a value independently, or NONE_KNOWN
    scope_limits:  what the entry does not reach
    thin_links:    inferences-of-inferences, marked as such
    would_change:  conditions that alter the entry
    reinspect:     interval, or UNSET
    owner:         name/role, or UNOWNED
    decay_class:   COUPLED | CONTINUOUS | REVISABLE | CONSTITUTIVE | UNSET
```

`status` and `term_status` are independent axes. A measurand can be
NOT_MEASURED and NAMED, or OBSERVED and UNNAMED, and the schema takes
any combination.

## What the check does and does not do

```
    fails an entry       a required key absent, or present and empty
                         a key repeated
                         a value outside a declared closed vocabulary
                         a malformed header line (reported file:line)

    does not             score, rank, weight or interpret
                         read entry bodies
                         judge whether a value is a good choice
                         treat a sentinel as a failure
```

**UNSET / UNOWNED / NONE_KNOWN are valid values.** The check asks
whether a key was DECLARED, not whether it was filled. An entry whose
`reinspect`, `owner` and `decay_class` all read sentinels passes.

That is the point of the sentinels: an absence that was decided is a
different state from an absence nobody looked at, and the header has to
be able to say which.

## Current state of the sentinel fields

Every entry here reads:

```
    reinspect:    UNSET       no interval has been set for any entry
    owner:        UNOWNED     no entry has an owner
    decay_class:  UNSET       see below
```

`decay_class` takes a closed vocabulary -- COUPLED, CONTINUOUS,
REVISABLE, CONSTITUTIVE -- that arrived without definitions. Assigning a
class from a vocabulary whose terms are not defined would put a reading
into the field that nothing supports, so every entry declares UNSET and
the field waits for the definitions. That is the largest open item in
the repository.

## Adding an entry

1. `entries/<ID>.md`, header block first, blank line, then body.
2. All twelve keys. A key you cannot fill takes its sentinel; a key with
   no sentinel is filled or the entry does not pass.
3. Body states procedure and scope. Not results, not arguments.
4. `python3 check_entries.py` and read the report.

Ids are permanent. A superseded entry keeps its id and changes its
`status`; it is not renumbered and not deleted.

## Index

`REGISTRY.txt` is generated by the checker: id, title, status, owner.
It is regenerated on every run and is not edited by hand.
