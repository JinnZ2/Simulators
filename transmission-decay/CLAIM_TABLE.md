# transmission-decay — CLAIM_TABLE

`TD_001..TD_008`. Claims about the delivered `SOURCE_DROP.md`.

**The study is not run here and is not simulated.** It requires
fieldwork and collective consent, and its own ethics section says *"A
study that extracts a decay rate while accelerating the extraction is
self-defeating."* No synthetic valley, informant, account, or
transmission chain stands in for a real one anywhere in this folder,
and nothing here is a statement about any community or any body of
knowledge.

What is computed is the design's own arithmetic — which of its outputs
one valley can carry — and that needs no field data.

## TD_001 — the absent scheme landed

`revision-mechanism` `RM_008` recorded M1–M8 as named, absent, and
**not reconstructed**, with the stated falsifier *"the companion study
landing."* It landed. That claim now reads CLOSED, the scheme is
**imported** from `transmission-decay.scheme.COMPONENTS` rather than
described, and the two folders cannot drift.

**The arrival is what shows the refusal was right.** The delivered
components are a hazard-specific vocabulary:

    M1  source identified        M5  timing/seasonality
    M2  trigger named            M6  precursor signs
    M3  mechanism stated         M7  ACTION rule
    M4  routing correct          M8  chained consequence

*Routing correct*. *Precursor signs*. *Chained consequence*, glossed
as the coupling component. No reasonable invention would have produced
that set, and every number keyed to an invented scheme would have been
about the invention rather than about transmission.

That is the `PB_001` / `CW_004` rule paying off in the one way it can
be observed to: the data arrived and did not match what a
reconstruction would have contained.

**Falsifier:** none. The scheme is here and parses.

## TD_002 — the most useful output is the expensive one

> *Component order is the most useful output.*

And then two questions that are not orderings:

> *If M7 outlives M3, transmission is preserving what to do while
> losing why.*
> *If M8 drops first, that is direct evidence that chained structure
> is the least transmissible component.*

Those three cost very different amounts. Informants coded per chain
position, against an arbitrary declared retention profile:

    n      full 8-order   M8 first (1 v 7)   one named pair
    5      0.000          0.360              0.754
    10     0.000          0.570              0.867
    20     0.007          0.753              0.919
    40     0.060          0.883              0.959
    80     0.167          0.960              0.997
    160    0.360          0.997              1.000

**The full eight-component order is out of reach at any plausible
one-valley sample** — 0.7% at twenty informants per position, and
still about a third at a hundred and sixty. *"M8 drops first"* is one
component against seven, so seven comparisons must all land, and it
costs around forty. **A single named pair — which is the form both
headline questions take — is affordable at ten to twenty.**

So the design's stated most-useful output is not the one it can get
from one valley, and its own two questions are. That is actionable for
someone about to run it: ask the pairs, report the ordering as
unresolved, and say which pairs were decidable at the n obtained.

The retention profile behind the table is **arbitrary and declared**,
spaced only to make the arithmetic runnable. It is not a prediction
about any component, because which component drops first is the
design's output and inventing it here would answer the question the
design exists to ask.

**Falsifier:** an ordering statistic that recovers eight ranks at
small n, or a headline question that genuinely requires the full
order.

## TD_003 — the half-life's resolution is a property of the axis

> *half-life — chain position at which mechanism score reaches half
> its C0 value*

    levels                C0, C1, C2, C3+
    ordered positions     3
    open catch-all        C3+
    intervals available   3
    finest statement      "between C0 and C1"

A half-life read off this axis names an interval between two adjacent
levels and cannot be finer. No number of informants changes it — it
follows from there being four levels, and it is a `G-RES` pair where
the feature is a half-life and the instrument is a four-point ordinal
scale.

`halflife_bracket()` therefore returns a **bracket and never an
interpolated value**: interpolating between C1 and C2 asserts a metric
the design does not define, since chain position is ordinal. It also
keeps three states apart — bracketed, *not reached on this axis* (the
score never halves within four levels, which is not the same as
absent), and no data.

**Falsifier:** a metric on chain position that licenses
interpolation — which would need the hops to be equal-interval, and
the design does not claim they are.

## TD_004 — `C3+` is not a position

> *C3+  no traceable chain to a witness*

C0, C1 and C2 are defined by counting hops from a witness. C3+ is
defined by the **absence** of a traceable chain. That is a different
kind of thing: an informant with four traceable hops and one with no
traceable chain at all both land in C3+, and the second is not a
measurement of distance.

So a decay curve fitted across the four levels assigns the coordinate
`3` to a category that does not have one, and the last point of the
curve is doing different work from the first three.

This is not fatal and it is cheap to state: report C0–C2 as the fitted
axis and C3+ as a separate stratum, or split it into *traceable, more
than two hops* and *not traceable*. The second is the one that carries
the design's own `OUT-MIGRATION SURVIVORSHIP` point, since a lost
chain and a long chain are different losses.

**Falsifier:** a C3+ stratum in which every informant has a countable
hop number.

## TD_005 — `M3` vs `M7` is asked twice, under two pressures

This study asks: does the **action rule outlive the mechanism** under
transmission decay — across chain position, with time and hops as the
pressure.

`revision-mechanism` comparison 3 **predicts** that mechanism-level
components survive at higher rates than rule-level ones — across
environmental change, with condition-shift as the pressure — and names
the reverse as *"the failure mode worth warning about."*

Same component pair, same coding scheme, two different selection
pressures. **Neither document says whether the same ordering is
expected under both**, and there is no reason it must be: a component
can be easy to transmit and fragile under change, or the reverse.

That is not an inconsistency. It is an untested transfer sitting
between two studies that share a vocabulary, and it is worth stating
before either is run, because a result from one will be read as
bearing on the other.

The stronger version: if `M7` outlives `M3` under transmission **and**
`M3` outlives `M7` under change, then the two pressures select
oppositely on the same pair — which would be the most interesting
outcome available from running both, and neither design currently
frames it as a prediction.

**Falsifier:** an argument that transmissibility and
change-robustness are the same property for a knowledge component.

## TD_006 — two absences designed in

> *OUT-MIGRATION SURVIVORSHIP — valleys that lost population after an
> event have lost carriers. **Absence of C2/C3 informants is data, not
> a sampling failure.***

That is the absent-vs-known-negative repair on the **sample**: an
empty stratum is a measurement, not a gap in coverage. Stated before
any fieldwork, in a confounds list.

> *LANGUAGE AND REGISTER — mechanism may be encoded in idiom, ritual
> calendar, place names, or song rather than expository form. An
> account coded S1 may be M-rich in a form the coder cannot read...
> Largest threat to validity and not fully removable.*

That is the same repair on the **coding**: `S1` is *"narrative with no
M-components"* and the drop says outright that it conflates *no
mechanism present* with *mechanism present in a form I cannot read*.
It names this the largest threat, marks it not fully removable, and
gives the remedy (a local co-analyst) plus what to do without one
(report the coding as frame-limited).

Naming your own largest validity threat and declining to claim it is
solved is rare, and it is what makes `S1` reportable at all.

**Falsifier:** none — these are design properties and both are
present.

## TD_007 — the instrumented record is the arbiter

> *Correctness is checked against the instrumented record, not against
> the interviewer's expectation.*

That is the right rule against the interviewer, and it makes the
**physical channel the arbiter of the knowledge channel** — which is
the asymmetry the drop opens by naming:

    physical hazard channel  ->  instrumented, funded, monitored
    knowledge channel        ->  footnote

A component the instrumented record does not contain scores as
incorrect. So a transmitted account that is right about something the
satellite inventory has no field for is coded as decay. `M8`, the
chained-consequence component — *what the flood loads downstream* — is
the most exposed, because a coupling across processes is exactly what
`gap-markers` `SCR-05` records the hazard literature as splitting on
origin rather than behaviour.

Not a defect: the alternative is the interviewer's expectation, which
is worse and which the drop rules out for that reason. What it costs
is that the measured decay rate is partly a measurement of the
instrumented record's coverage, and the drop does not say so on this
measure.

Cheap addition: code *not in the record* as a third value alongside
correct and incorrect. That is the same third state `S1` and the C2/C3
absence already get.

**Falsifier:** an instrumented record with a field for every
M-component, at which point the arbiter is complete and the concern
dissolves.

## TD_008 — nothing here is evidence about transmission

Every result above is about the design's arithmetic and vocabulary.
None is evidence for or against decay, a half-life, a component order,
or any of the three falsifiers.

The ethics constraint binds this audit and not only a fieldworker. The
available shortcut for a study one cannot run is to simulate it —
generate informants, generate accounts, generate a decay curve — and
publish a table that reads like a result. Into a CC0 repository that
is a fabricated claim about real communities, and the drop's own
sentence covers it: *"A study that extracts a decay rate while
accelerating the extraction is self-defeating."*

The `M7` sensitivity note binds harder still: *"the ACTION components
may be more sensitive than mechanism ones — do not assume publication
is neutral."* Nothing here contains or invents an action rule.

**Falsifier:** run it, with consent, and publish the pairs that were
decidable at the n obtained plus the cells that were not.

## TD_009 — a silent pass in my own parser

`scheme.py` is the module that reads M1–M8, S1–S3 and C0–C3+ out of
the delivered document. It had no `__main__` block, so

    python3 transmission-decay/scheme.py --selftest

exited **0, printing nothing**. Every other module in this tree
answers that flag with a count and a verdict, so an operator sweeping
the folder reads a clean pass from the one file that ran no check at
all — and it is the file every number downstream depends on, since a
mis-parse there is silent by construction.

This is the `DL_005` / `CC_006` shape (a well-formed report over an
empty corpus, exit 0) at a new site: not an empty report but **no
report**, from a flag the module never claimed to accept and did not
refuse either.

Repaired by refusing rather than by adding checks. `scheme.py` has no
checks of its own — duplicating `selftest_power.py`'s into it would be
copying, which is what five stale copies of one gate came from
(`MF_006` / `MF_011`) — so the flag now exits **2** and names where
the checks live, and a bare invocation renders the parsed scheme so
what was taken from the drop is readable without importing anything.

Both branches are pinned in `selftest_power.py`: the refusal must
return 2 and must name the runner, and the bare render must exit 0 and
name every component and chain position. A regression to a silent pass
turns them red.

**Falsifier:** a reading under which a silent exit 0 on an unrecognised
flag is the correct behaviour for a module in a tree where every
sibling answers that flag with a count.
