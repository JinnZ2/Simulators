# fragility-cascade/legacy

Files kept for git-history reproducibility. **Not** used by `run_all.py` or
imported by any live module. If you're auditing today's numbers, ignore
this folder.

| `scale_invariant_audit_v1.py` | `../scale_invariant_audit.py` (v2 log-frame) | v1 measured `delta = \|D_n − D0\| / D0` — a LINEAR metric that contradicts the multiplicative Nautilus principle it audits. | `modes_v1.py` | `../modes.py` (v2 clock handshake) | v1 stored `reads_well` and `blind_to` as scalar strings, forcing the table's own-blind-spot detection through a content-token-overlap heuristic that produces false positives (unrelated modes sharing generic words) and false negatives (related modes in different vocabulary). v2 makes both fields `List[str]` and computes the blind spot as a true set difference `blind - seen` — a mode's blindness is uncovered iff no other mode's `reads_well` list literally contains the same string. v1's audit returned a nested dict; v2 returns a flat `List[str]` matching the family's other audit surfaces. v1 lacked the `resolve_clock(mode_name, referent_volatility)` bridge to `clock.py`; v2 exposes it as the single call site joining the mode table to the freshness clock, so downstream modules import `modes.resolve_clock` instead of walking `MODES` directly. v1 also missed the both-clocks-set LOUD (`clock.freshness()` takes the faster; confirm intent) and used a plain `ValueError` — v2 uses `IncompleteMode(ValueError)` for grepability. | `clock_v1.py` | `../clock.py` (v2 decay registry) | v1 had ONE decay term: elapsed calendar time (the mode-supremacy move performed on clocks — treating one channel as universal). v2 registers six channels — `time`, `disuse` (observer out of practice), `use` (retrieval rewrites the record), `constancy` (adaptation to unchanging stimulus), `transmission` (per-hop fidelity, Eigen error threshold), `diffusion` (independence itself decaying) — each with `measures`/`blind_to`/`fn` fields via a `register_decay_channel()` door that raises on empty `blind_to`. Critically, v2 splits channels across three TARGETS (`claim`, `mode_sensitivity`, `independence`) and computes the governing channel WITHIN each target, never across — taking the min across channels that decay different objects is a category error. A claim can be fresh, unreadable, and no longer independently supported at the same time, with three separate readings and three separate consequences. v2 preserves v1's `freshness()` API verbatim as the time-channel-only entry point so `echo.py` and any other v1 client works unchanged; `Observation` + `decay()` is the new richer surface. `max_chain_hops()` added for the Eigen error-threshold bound on transmission depth. |
| `modes_v2.py` | `../modes.py` (v3, built against decay registry) | v2 shipped when `clock.py` still had one decay channel; each mode row supplied `half_life_days` or `tracks` and that was the whole clock story. When clock.py v2 introduced six channels, v2 modes rows became silently under-specified for five of them: any claim held by a v2 mode reports UNDETERMINED across five of six decay targets. v3 fixes this three ways. (1) Six per-channel parameter fields on `Mode` (`mode_half_life_days`, `practice_half_life_days`, `retrieval_fidelity`, `adaptation_half_life_days`, `hop_fidelity`, `field_mixing_half_life_days`), one per registry channel. (2) `channels_na: Dict[str, str]` for explicit inapplicability with a REASON — "n/a" is not a reason. (3) Silence (neither parameterized nor NA) fires a per-channel LOUD flag naming the target that will read UNDETERMINED. Also adds `criterion` as a fifth required field — the bias/threshold statement from signal detection theory, held separate from `reads_well`/`blind_to` (sensitivity/d'). Replaces v2's `resolve_clock()` with a richer `to_observation(mode_name, now, **facts)` + `read(mode_name, now, **facts) -> clock.Decay` pair, and audit gains degeneracy detection (identical `reads_well` between two modes = redundant if `blind_to` also identical, degenerate if different — degeneracy adds robustness, redundancy doesn't). |
| `divlog_v1.py` | `../divlog.py` (canonical) | Pre-spec draft: mutable `Entry`, no `id` field, `residual()` returned four outcomes, API was `append/read`. Superseded during first spec pass. |
| `divlog_v2.py` | `../divlog.py` (v1 against SPEC_drift_mesh, formal) | First-pass spec-conforming implementation (frozen Entry, id property, five residual outcomes including INTERMITTENT, load/history API). | `entrain_v1.py` | `../entrain.py` (v1 against SPEC section 2) | The retired file implemented `reference_version(state)` as a caller-supplied fingerprint (took the state dict as an argument) and had no `Peripheral` / `PERIPHERALS` registry. `phase()` was a stateless comparator on `(recorded, current)`. The SPEC version adds: (1) `Peripheral(name, entrain_interval_days, last_entrained, ref_version)` dataclass + `PERIPHERALS` registry + `register_peripheral()` door; (2) `reference_version()` takes NO args and reads clock.CHANNELS + clock.VOLATILITY directly — the enforcement claimed by D10; (3) `Phase` dataclass carries `days_since_entrained` + `interval` + LOUD flags; (4) `phase(name, now)` looks the peripheral up in the registry, computes the four-state phase against the CURRENT primary; (5) `entrain(name, now)` records the pull — writes `last_entrained` and `ref_version` on the registered Peripheral; explicitly does NOT mutate any reading. The retired module still worked as a stateless fingerprint tool but couldn't express the scheduled-pull-back discipline the SPEC requires. |
| `syndrome_v1.py` | `../syndrome.py` (v1 against SPEC section 3) | The retired file operated on `divlog.Entry` objects directly: `parity()`, `trace()`, `mesh()` all consumed and returned `Entry` collections. The SPEC version separates `Reading` (what a module produces) from `Entry` (what the log stores). This is load-bearing: parity operates on peer READINGS before anything is logged, and raises on cross-target comparison (T1 / I2) — an invariant the earlier design couldn't enforce because `Entry.target` was already committed at construction. Also new: (1) explicit `Syndrome(kind, a, b, detail, loud)` return type from `parity()`, replacing `Entry` returns; (2) `digest(inputs)` function that renders `None` as the string `"None"` so a missing input is part of the fingerprint (D3 encoded here); (3) `KIND_*` constants for the SPEC's five parity kinds plus TRACE and PHASE syndromes; (4) `trace(reading, now, inputs)` takes the raw inputs as an optional argument (the Reading only holds the digest, so trace can't recompute without them); missing inputs → `KIND_MISSING` LOUD, honestly (I4); (5) `mesh(readings, now, inputs_by_reading)` groups by (target, subject) before pairwise parity — cross-target comparisons are impossible by construction, not by check. |
| `instruments_v1.py` | `../instruments.py` (v2 with D11) | v1 R2 had two resolution states: `OPEN` (name a harm + a harmed party) and `CONTESTED` (record ≥ 2 frames). The operator broke `OPEN`: for autopsy, fetal tissue, a stillborn eaten by the pack, whether a harmed party EXISTS is the same contested question the OPEN branch was supposed to resolve. The discriminator smuggled in the thing it was meant to decide. OPEN was CONTESTED that hadn't been noticed. v2 (D11) replaces `OPEN` with `DEPENDENCY` — a STRUCTURAL claim on the physical stack `energy → earth → ecology → biology → culture` (base first, ordering not editable, physics not moral). New R2 fields: `reaches_layer` (must be in `DEPENDENCY_STACK`, else door raises); `removes_above` (non-empty list of what collapses when that layer is removed, else door raises — an unarticulated collapse is a gesture, not a claim). The value question does not disappear; it stops pretending to be settled at the door. R2/DEPENDENCY reports the dependency, not a verdict on it. Retired v1 fields (`harm`, `harmed_party`) are no longer present on `Instrument`. `emit()` now inlines `dependency_stack` in every handoff JSON so downstream sees the stack the module is refusing to reorder. |
