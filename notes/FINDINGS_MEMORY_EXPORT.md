## What this reading got wrong

Four first-pass searches were too narrow. All four were caught by widening the
search, none by reading more carefully.

1. `.md`-only grep reported `emergence-stability-simulator`'s claim statuses and
   tool-vs-identity framing as missing. They were in a samples JSON and in code.
2. Hyphen-only matching reported `info-taxonomy` and `rubric-backcasting` as
   absent. Both exist under the underscore convention.
3. The same defect recorded `shape-index` twice as "existing on neither side"
   while `predicate-difference/shape_index.py` was in the tree. The substance
   survived — that file states in its own header that no shape-index format
   exists in the repository — but the search could not have found it.
4. A probe for a `rejections` key in `grade-stop.json` found none and would have
   reported the memory file's "4 grounded rejections" as unsupported. The key is
   `rejected`. Caught before recording.

Two statements written into the folder README were also corrected rather than
narrowed: that nothing in the folder carries a claim table or refutation
protocol (`diversity-collapse-model` does), and that the export's references
split by kind, `[[...]]` for memory and plain names for repositories
(`geometric-manifold` links two repositories as wikilinks).

Defect 2 is the same hyphen/underscore failure `uninstrumented/CLAIM_TABLE.md`
records against the repo under `UNI_060`. It was reproduced here independently
before that record was found.
