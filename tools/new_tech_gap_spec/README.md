# new_tech_gap_spec

Written from the risk-mitigation side for common workers/responders;
less hedged than institutional reports by design.

An INSTRUMENT for reading a new technology before it ships: the gaps,
the unmeasured quantities and the scope limits. It is not a finding
and not a position on any product.

| File | What it is |
|---|---|
| `spec.md` | the spec: disciplines, 14 standard interfaces, 10-section checklist, forward trajectories, cross-cutting gaps, clock-rate mismatch |
| `case_thruster_roadster.md` | worked case 1: a road car with cold-gas thrusters |
| `case_ai_wearables.md` | worked case 2: always-on AI wearables at work |

Status tags on every item: OBSERVED / DERIVED / PROPOSED / UNMEASURED.
Each case opens with a citation table for its "Reported" lines, marked
VERIFIED / CORRECTED / NOT FOUND. Sources were read through search
results only (checked 2026-10-16); primary pages were not opened.

## Copies

The four files are kept byte-identical in two places:

    JinnZ2/Simulators     tools/new_tech_gap_spec/
    JinnZ2/method-layer   tools/new_tech_gap_spec/

Neither copy is derived from the other. A change lands in both, or the
two are reported as drifted (`sha256sum *.md` in each folder must
match).
