# Glyph: a relation, not a symbol

CC0. A reusable reasoning move, delivered 2026-10-25, co-authored. The
delivered text is kept verbatim in section 2 and nothing in it is edited.

Companions: `tools/inward_turn.md` (point a critique back at the home
record) and method-layer `reasoning-layer/` (check_record: an unrecorded
skip is E3, a defaulted slot). Simulators `held-gaps/OPEN_QUESTIONS.md`
gap 1 asks for a measure of the E3 drift rate.

Tags: OBSERVED = stated in a source or seen in the field; DERIVED =
follows from what is stated here; PROPOSED = untested.

## 1. When to pick it up

- pick up when: a reading is being taken from a label, a rule or a prior
  result as if it were fixed, and the conditions it applied under may
  have moved.
- pick up when: a check has passed for a long time without varying. That
  is where E3 lives.
- skip when: the quantity is defined by convention and no environment
  feeds it (a unit definition, a declared vocabulary).

The procedure is six steps and the error types are four. Use the error
types as a checklist after the fact: name which of E1-E4 a miss was
before repairing it, because the four call for different repairs.

## 2. Delivered text (verbatim)

```text
GLYPH — model-facing definition                         [DRAFT / co-authored]

NOT:  a symbol, character, or icon to decode into a fixed meaning.
IS:   a generating relation over an environment, like a differential equation.
      It does not return an answer. It returns a family of possible outcomes;
      the measured conditions select which one applies.

REASONING THROUGH THE GLYPH = a procedure, run every time:
  1. ENUMERATE the variables the environment actually holds
     (physical: temperature, flow, sediment, soil biota, predators...
      relational: who depends on whom, whose feedback loop is how close)
  2. MEASURE each one now. Yesterday's value is not today's value.
  3. TEST every slot. No slot is assumed from history or from a claim.
  4. CHECK the observer: own state, own frame, own calibration regime.
  5. RUN the relation -> option set, ranked by what the environment supports.
  6. RE-RUN when conditions change.

ERROR TYPES (the glyph holds; the reasoning fails):
  E1 dropped variable   -> left out sediment, so the eddy count is wrong
  E2 stale conditions   -> used pre-flood values on a post-flood stream
  E3 defaulted slot     -> "this party is coupled to the land" assumed, not tested,
                           because every past party was. (historical instance:
                           settler contact, treaties, land "ownership")
  E4 unchecked observer -> dehydrated, hungry, or frame-blind sensor

WRONG READ: "glyph = static object with a reading"
RIGHT READ: "glyph = relation; the reading comes from the conditions you feed it"
```

## 3. What this note does not do

[PROPOSED] Nothing here measures how often each error type occurs, and
no instrument checks the six steps were run. The procedure is a
discipline, not a gate.
