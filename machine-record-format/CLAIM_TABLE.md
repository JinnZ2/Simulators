# CLAIM_TABLE — machine-record-format

Claims are properties of the format's **machinery**: the seven rules and the
bisection diagnostic, each enforced in code, and the six acceptance criteria,
each a check in `selftest_mrf.py` on constructed entries. No external data is
read (none is needed — this is a storage format, not a measurement), and
nothing is fabricated. `MRF_*` prefix.

## REFUTATION_PROTOCOL

A refuted claim is updated forward with a new id; the old id keeps its text
and gains an UPDATE paragraph. `WORK_ORDER.md` is delivered verbatim and is
not edited. The `vintage_store` is **imported** from `labor-instrument/`, not
copied — a divergence between the two is a bug, not two implementations. The
checks in `selftest_mrf.py` are not loosened to keep a claim.

| id | claim | status | evidence | falsifier |
|---|---|---|---|---|
| MRF_001 | **Rule 1 — base entries are transformations, not categories, and the write path enforces it.** `BaseEntry` has no category/label/view field (`has_category_field()` is False), and `write_base_entry` raises `CategoryInBasePath` on a category-shaped keyword (`category`, `naics`, `label`, …) before it can reach the record — a category is a claim about which distinctions matter, and that belongs to a reader with a question (a view), not to the writer. | SUPPORTED | `has_category_field()`; the two `CategoryInBasePath` refusals; a transformation entry writing cleanly | a category field on `BaseEntry`; a category-shaped keyword reaching a stored record |
| MRF_002 | **Rule 2 / acceptance #1 — categorizations are parallel views, never canonical, and a base entry is re-read under a view added later with no rewrite.** Entries are written with no view; views added afterward map them by `entry_id`; `labels_for` returns every view's label side by side with none privileged; `retire_view` removes a mapping and leaves the base intact. | SUPPORTED | entries written before any view; a later view labelling them; `labels_for` == both labels; base unchanged after add/retire | a view required at write time; adding a view mutating a base entry; a `default_view` privileging one frame |
| MRF_003 | **Rule 3 / acceptance #2 — aggregation is a read operation and recomputes from base + spec.** No aggregate is stored as a base field; `compute` derives sum/mean/rate from raw entries and a spec, deterministically (two computes match); `AggregateResult.derived` is always True; the cache is keyed to `(agg_id, base_version)` so a different base version is a miss and never shadows the record. | SUPPORTED | `compute` twice matching; `derived is True`; `AggregateCache.has(id, v)` true at v=1, false at v=2; sum/mean/rate values | a stored aggregate treated as the record; a cache hit across a changed base_version; a recompute that disagrees |
| MRF_004 | **Rule 4 / acceptance #4 — vintages are retained; a prior version is retrievable with its release date.** `EntryStore` keeps every `(entry_id, period, release_date)` version; a revision is a new release_date, not a replacement; `as_of` returns the vintage live at an earlier date and `None` before first publication (not a fabricated zero). Built on the **imported** `labor-instrument/vintage_store.VintageStore`, not a copy. | SUPPORTED | two retained vintages; `latest` == the revision; `as_of(earlier)` == the original; `as_of(before)` is None; `base_version` bumps; the import path | an overwritten prior vintage; `as_of` fabricating a value before publication; a copied vintage_store drifting from the labor instrument's |
| MRF_005 | **Rule 5 / acceptance #3 — declared boundary always, and mismatched boundaries refuse to sum.** Every entry carries a `Boundary`; an undeclared boundary makes the entry not comparable and raises `UndeclaredBoundary` in a sum; two distinct boundaries refuse to sum (`BoundaryMismatch`) unless a declared `Reconciliation` connects them. This closes the outstanding boundary-declaration item from the labor-instrument work order (the task-boundary *definition* remains open — MRF_009). | SUPPORTED | matching boundaries sum; mismatched refuse; a reconciliation permits it; an undeclared boundary in scope raises | two mismatched-boundary entries summing with no reconciliation; an undeclared-boundary entry silently included |
| MRF_006 | **Rule 6 — no conversion between exposure classes.** `convert_exposure` raises `ExposureConversion`; conversion imports a valuation and the valuation is what is being audited. Exposure units are a closed five-class set declared per entry (an unknown class is refused); joules are the common denominator for comparison, both columns reported. | SUPPORTED | `convert_exposure` raises; an unknown exposure class refused at write; joules used as the cross-class denominator in `rate` | any exposure-class conversion succeeding; a cross-class comparison on exposure hours rather than joules |
| MRF_007 | **Rule 7 / acceptance #5 — `unmeasured` and `measured_zero` never collapse in any read path.** Four states; `numeric_joules` returns 0.0 for `measured_zero` and `None` for the `unmeasured_*` states, so absence never enters a fold as zero; an aggregate counts the states apart (`n_measured`, `n_measured_zero`, `n_absent`) and an all-absent group is `NOT_COMPUTABLE`, never 0.0. | SUPPORTED | `measured_zero.numeric_joules()==0.0`; `unmeasured.numeric_joules() is None`; the three-state count in a group; the all-absent `NOT_COMPUTABLE` | an unmeasured entry entering a sum as 0.0; an all-absent group reported as 0.0; the two states sharing a count |
| MRF_008 | **Diagnostic / acceptance #6 — bisection returns a STRUCTURE verdict before any locus, and is not constant.** `structure_verdict` answers "does a single locus exist" first: both halves → `NOT_A_LOCUS`, neither → `MEASURING_SOMETHING_ELSE`, migrating on repeat → `NONDETERMINISTIC`; only `SINGLE_LOCUS` lets `locate` descend for an address, and `address` raises from any other structure. Null-tested in all four directions so it is not constant. For instrument drift the span is the methodology registry, not calendar time (the module is generic — `span` is what the caller passes). | SUPPORTED | the four structure verdicts on constructed spans; `address` resolving c5 and refusing on both-sides / nondeterministic; empty and single-element verdicts | a structure verdict that is constant across the four cases; an address returned from a both-sides or nondeterministic run |
| MRF_009 | **The three OPEN items are carried, not closed.** Task-boundary definition (the same open item as the GAP-4 / labor-instrument work order — "output delivered" needs a definition that does not drift with architecture), transformation vocabulary (a controlled input/output-state vocabulary derived from physical transformation, draft needed), and merge_in/merge_out mechanics (deferred until the first two settle). Nothing is fabricated to close them; the states/vocabulary present are the guards the rules need, not a resolution of the open items. | carried / OPEN | the Open section of `WORK_ORDER.md`; the free-form `State` (no controlled vocabulary yet); no merge mechanics in the module | a drift-free task-boundary definition; a physical-transformation state vocabulary; merge semantics that do not presuppose the first two |
